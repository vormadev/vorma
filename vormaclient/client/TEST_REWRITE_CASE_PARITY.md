# vormaclient/client Case-Level Parity Ledger

This file is the strict, case-level parity source of truth for legacy migration.

## Rules

- Every legacy test case must be mapped before legacy deletion signoff.
- New mapped tests must assert first-principles-correct behavior.
- Legacy assertions that are weak or implementation-coupled must not be copied.
- If a legacy case is intentionally not reproduced, record explicit rationale in
  `Decision` and reference strict replacement coverage.
- If behavior is truly ambiguous, ask the user immediately (no deferred open
  queue).
- Keep this file synchronized with generated title data in
  `TEST_REWRITE_SHOULD_MAP.json` by running
  `node vormaclient/client/scripts/generate_test_case_maps.mjs`.

## Status Keys

- `pending`: not yet case-mapped.
- `mapped-strict`: replaced by strict first-principles
  contract/integration/regression tests.
- `dropped-legacy-weakness`: old test assertion intentionally not carried
  forward because it was weak/non-principled; replacement and rationale
  required.
