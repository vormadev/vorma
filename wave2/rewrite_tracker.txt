Non-Negotiable Constraints
- Wave2 runtime/buildtime boundary must stay strict.
- `wave2` (runtime-facing) must not import `wave2/wavebuild`.
- Wave must remain framework-agnostic.
- Framework-specific behavior belongs in adapters (`wavefw`) or framework-owned packages.
- Keep code minimal, elegant, and outcome-driven (no transitional compatibility layers in this rewrite).

Design Principles Locked In
- Planner chooses terminal goals (effects), not imperative step scripts.
- Effects are ensure-style outcomes (idempotent guarantees).
- Batch planning reduces via union + dedupe + mode filtering + arbitration.
- Execution should lean on `kit/tasks` for dependency sequencing and maximum parallelism.
- Production should reduce batch changes to deduplicated prod-applicable goals and run each once.

Current Code Reality
- `wave2/wavebuild/wavebuild.go` is intentionally contract-first.
- It defines interfaces and lightweight orchestration wiring:
  - Facts collection
  - Event classification
  - Planning
  - Arbitration
  - Task-root execution
- It includes canonical goal, arbitration, and event-rule catalogs as data.
- It includes a concrete `EventRulePlanner` for event-rule reduction into
  deduplicated terminal goals and framework signals.
- It includes a concrete `RuleSetArbiter` and `NewCanonicalRuleSetArbiter`
  for data-driven rule application.
- It includes a concrete `DefaultTaskRootExecutor` that runs deduplicated
  terminal goal roots via `kit/tasks` in one execution context.
- It deliberately returns `ErrNotImplemented` when core implementations are not attached.
