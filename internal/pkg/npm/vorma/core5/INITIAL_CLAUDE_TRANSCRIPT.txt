Now runtime.ts. This is the largest remaining file by far. A few preliminary notes:
Runtime structure. The runtime owns: the model, the platform, a dispatch loop, three maps (navigation waiters by call ID, refresh waiters by call ID, submit waiters by call ID), an abort handle registry, a timer handle registry, a module cache, a client loader registry, and a route loader registry. Dispatch is synchronous within a single call. Async effects (fetch, prepare, view transition) settle later. When a fetch effect fires, the runtime starts the work and ignores the result for now. This re-enters the reducer cleanly because the model has progressed in the meantime.

A few notes before code. This subsystem handles a single effect type: prepare_route. Its job is to take a RoutePayload, run the work needed to make it publishable, and return a PreparedRoute (or a failure).
The work breaks down into:
Module imports. Each route in the payload has a module_url. Import them in parallel (well, in sequence — the cache dedupes), populate the module cache, register any client loaders the modules expose.
