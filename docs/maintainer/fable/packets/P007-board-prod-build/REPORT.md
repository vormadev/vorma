## Escalations / open questions

Framework-implicated finding (ticket filed, no framework code touched):
`vorma::middleware::etag()` composed inner to `vorma::middleware::response_body_timeout()`
— the more natural declaration order — silently produces zero ETags on any response, ever.
Root cause: the timeout layer's `tower-http` body wrapper (`TimeoutBody<B>`) never
forwards the wrapped body's exact `size_hint` (defaults to "unknown" per
`http_body::Body`'s own default), and `etag` only tags a response when it can see an exact
size. Proven with an isolated minimal reproduction pinpointing this exact layer as the
sole cause. Full trace + four ranked remediation options (doc-only / make `EtagLayer`
tolerant of unknown hints / fix `tower-http` upstream / a composed pre-ordered helper) in
the ticket, cross-referenced at census F-23. Doc-only alone conflicts with the project's
no-footgun-smoothed-by-docs rule; the rest is the maintainer's call.

Make target proposal (not added unilaterally): a `board-prod-smoke` target driving a new
`vorma-xtask` subcommand (matching the existing xtask pattern) that boots the built binary
on a scratch port, curls a couple of routes for 2xx + the build-id header, sends SIGTERM,
and confirms clean exit — a fast no-browser sanity check distinct from `make e2e-smoke`'s
deeper Bombadil `test-prod`.
